Chapter 10: Connecting to Enterprise SIEM and Log Aggregators: Writing to Splunk, Elastic, or OpenTelemetry

Every access evaluation, tool dispatch, and anomalous threshold breach across an agent's lifecycle produces security telemetry. To meet compliance obligations and detect active attacks, this telemetry must stream into an enterprise SIEM (Security Information and Event Management: a centralized platform that aggregates, correlates, and analyzes security telemetry across enterprise systems). However, synchronous logging directly inside model execution paths introduces network latency and risks crashing running agents if log servers become unreachable. Connecting to enterprise log aggregators requires a decoupled, non-blocking asynchronous pipeline that formats events according to common industry schemas, binds distributed trace contexts, and handles backpressure safely.

In this chapter, we use the incident response assistant (langchain-enterprise-incident-assistant) as a concrete demonstrator to show how to connect your enterprise LLM applications to SIEM platforms (such as Splunk, Elastic, or OpenTelemetry collectors) using langchain-security-extension. We examine how to configure AuditManager as a unified telemetry bus, extract and propagate W3C distributed trace headers, and ensure non-blocking, tamper-evident audit event dispatch.

A central architectural advantage of the langchain_security_extension.security_core design is providing a single, unified entry point (AuditManager backed by the AuditPublisherSPI interface) for connecting external aggregators. Rather than requiring individual Policy Enforcement Points (PEPs)—such as @secured_tool, SecureRunnable, SecureRetriever, or ingestion validators—to maintain independent logging logic and network connectors, all PEPs dispatch standardized security events to AuditManager. As a result, attaching, swapping, or multiplexing external log aggregators requires configuring publishers in a single location, keeping agent code clean and completely decoupled from observability infrastructure.

While the security library (langchain-security-extension) provides ready-to-use SPI publishers for enterprise platforms (including SplunkHecPublisher, ElasticCommonSchemaPublisher, and OpenTelemetryLogsPublisher), the demonstrator application (langchain-enterprise-incident-assistant) configures local JSON log forwarding (JsonFileAuditLogger) as its primary operational sink (the standard pattern for containerized nodes where agents like Fluentbit or Vector tail log volumes), with externalized settings to optionally enable SplunkHecPublisher directly when HEC credentials are supplied.

The Standardized Security Event Envelope

To eliminate proprietary log formats, security events adhere to an envelope compatible with both OCSF (Open Cybersecurity Schema Framework: an open-source, vendor-agnostic specification providing a unified taxonomy for security events) and ECS (Elastic Common Schema: an extensible specification defining a common set of fields for storing and analyzing event data in Elasticsearch):

Envelope Section Key Fields Operational Role
Header & Tracing event_id (UUID), schema_version, timestamp_utc, trace_id, span_id Enables distributed log correlation with W3C request traces.
Subject Principal subject_id, tenant_id, subject_roles, clearance Captures the immutable caller identity extracted from RunnableConfig.
Action & Target enforcement_point, action, target_resource Identifies the originating PEP and requested operation.
Decision & Verdict decision (ALLOW, DENY, HARD_ABORT), reason_code Records the authorization outcome and rule justification.
Sanitized Context payload_snapshot, diagnostic_reason Contains arguments and metadata scrubbed of credentials, API tokens, and PII.
Tamper-Evidence sequence_number, envelope_hmac Monotonic sequence counter and optional SHA-256 HMAC digest reserved for downstream append-only cryptographic forwarders (document chunks independently verify metadata integrity via sec:envelope_hash).

Asynchronous Publisher SPI and Ring Buffer Architecture

Decoupling log export from agent inference relies on the AuditPublisherSPI interface and the central AuditManager. Rather than blocking the model execution thread or relying on fragile asynchronous event-loop primitives, AuditManager dispatches events to a thread-safe bounded deque (ring buffer) monitored by a dedicated background daemon worker thread (AuditManagerAsyncWorker). If the downstream SIEM becomes slow or temporarily unreachable, AuditManager sheds load using DROP_OLDEST_WITH_METRIC, incrementing dropped_count while preserving system responsiveness.

Part 2: The Non-Blocking Ring Buffer (AuditManager)

To insulate agent execution from network delays, AuditManager dispatches events to a thread-safe ring buffer serviced by a daemon worker thread, applying load shedding (DROP_OLDEST_WITH_METRIC) when under extreme load:

SECURITY LIBRARY SNIPPET (INFORMATIVE) langchain_security_extension/security_core/audit.py
PYTHON 
# langchain_security_extension/security_core/audit.py (Ring Buffer Asynchronous Dispatch)
from collections import deque
import threading

class AuditManager:
    """Non-blocking ring buffer dispatch decoupling log export from agent inference."""

    def __init__(self, publishers: List[AuditPublisherSPI], capacity: int = 1000):
        self._publishers = list(publishers)
        self._capacity = capacity
        self._buffer: deque = deque()
        self._dropped_count = 0
        self._lock = threading.Lock()
        self._queue_condition = threading.Condition(self._lock)
        self._worker_thread = threading.Thread(
            target=self._worker_loop,
            name="AuditManagerAsyncWorker",
            daemon=True,
        )
        self._worker_thread.start()

    def record_event(self, event: "AuditEvent") -> None:
        """Applies in-flight PII sanitization and queues event into ring buffer without blocking."""
        with self._queue_condition:
            if len(self._buffer) >= self._capacity:
                self._buffer.popleft()  # DROP_OLDEST_WITH_METRIC load shedding
                self._dropped_count += 1
            self._buffer.append(event)
            self._queue_condition.notify()

def get_audit_events(file_path: str) -> List[JsonAuditEventRecord]:
    """Flushes active AuditManager and returns parsed audit events from the target JSON log file."""
    pdp = get_pdp_engine()
    audit_mgr = getattr(pdp, "audit_manager", None)
    if audit_mgr:
        audit_mgr.flush()
    if not os.path.exists(file_path):
        return []
    records: List[JsonAuditEventRecord] = []
    with open(file_path, "r", encoding="utf-8") as f:
        for line in f:
            stripped = line.strip()
            if stripped:
                try:
                    records.append(JsonAuditEventRecord(json.loads(stripped)))
                except json.JSONDecodeError:
                    pass
    return records

Code Hardening: Hooking Audit Telemetry and SIEM into Application Flow

Configuring the AuditManager in security_integration.py establishes the non-blocking publisher pipeline, but integrating telemetry into the end-to-end request lifecycle requires connecting five key components across the application:

  1. Configuring SIEM Endpoints: Exposing Splunk HEC credentials in app/config.py.
  2. Distributed Trace Capture: Extracting W3C traceparent headers in app/security/auth.py.
  3. Binding Trace Context into Security Identity: Transferring trace and span IDs to SecurityIdentity.attributes in app/security/models.py.
  4. Trace & Identity Context Propagation: Injecting RunnableConfig at the API entry point in app/routers/tickets.py.
  5. Perimeter Ingestion Telemetry: Emitting structured ticket:submit audit records in app/agents/guardrail_tests_telemetry_helper.py.

4. Propagating Correlated Identity into Agent Entry Runnables

In app/routers/tickets.py, the application bridges the request's security context into LangChain's execution graph using security_identity_from_context() and IdentityBridge.create_runnable_config(). When SecureRunnable wraps the agent entry point (such as triage_agent.triage), it automatically extracts trace_id and span_id directly from identity.attributes. Because this identity is preserved within LangChain's RunnableConfig under configurable["security_identity"], downstream graph nodes, chained runnables, and tools automatically inherit the trace and caller context without requiring developers to pass these details again as function parameters.

Upon successful entry verification, SecureRunnable automatically emits an authenticated entry audit event (IdentityBridge.record_auth_success) capturing the caller's identity, roles, clearance rank, trace_id, and span_id directly to AuditManager. Any subsequent tool executions, policy violations, or authorization denials across the lifecycle likewise emit standardized, trace-correlated AuditEvent records to the ring buffer automatically:
