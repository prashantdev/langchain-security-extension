Chapter 5: Security Labeling and Admission Control in the Ingestion Pipeline

Retrieval-Augmented Generation (RAG) is only as secure as the metadata stored inside the vector index. If document chunks are embedded without cryptographic boundaries, role tags, and multi-tenancy keys, downstream retrievers cannot reliably enforce authorization. Security labeling and admission control in the ingestion pipeline ensure that during the ETL (Extract, Transform, Load: a data processing pipeline that extracts raw data, transforms its structure, and loads it into a storage target) lifecycle, every chunk is stamped with a tamper-evident security envelope and validated against strict admission policies before embeddings are generated and stored.

The sec:* Chunk Metadata Envelope

Vector databases index flat key-value pairs alongside embeddings. To prevent namespace collisions with arbitrary source metadata (such as page_number or author), all access boundaries are unified under the reserved sec:* prefix:

  • sec:schema_version: Semantic schema version string (e.g., "1.0").
  • sec:tenant_id: Mandatory partition identifier enforcing multi-tenant isolation.
  • sec:document_id: Unique identifier linking chunks to their root parent source.
  • sec:chunk_index: Zero-based sequential integer denoting the chunk's position in the document.
  • sec:classification_level: Hierarchical data classification tier (PUBLIC, INTERNAL, CONFIDENTIAL, RESTRICTED).
  • sec:clearance_floor: Numeric clearance rank (0 ≤ PUBLIC < 1 ≤ INTERNAL < 2 ≤ CONFIDENTIAL < 3 ≤ RESTRICTED) used for fast numeric range pre-filtering.
  • sec:allowed_roles: List or delimited collection of RBAC roles entitled to read the chunk.
  • sec:envelope_hash: Cryptographic HMAC (Hash-based Message Authentication Code: a cryptographic signature verifying data integrity and authenticity) digest ensuring metadata fields cannot be altered inside the vector database.

Ingestion Lifecycle: Labeling, Enrichment & Admission Control

The security labeling and admission pipeline executes across four deterministic stages implemented as LangChain BaseDocumentTransformer primitives:

  1. Baseline Validation (DocumentSecurityTransformer): Inspects the raw document for mandatory baseline attributes (e.g., tenant_id, baseline clearance) before text splitting.
  2. Document Chunking: Uses standard LangChain text splitters (e.g., RecursiveCharacterTextSplitter) to divide the document into chunks while inheriting parent metadata.
  3. Chunk Enrichment (SecureDocumentChunkEnricher): Scans chunk text for structural markdown headers (e.g., ## [CONFIDENTIAL]) or invokes an external SPI (Service Provider Interface: an extensibility pattern allowing custom classes to plug into framework pipelines) to elevate classification tiers.
  4. Envelope Validation & Signing (SecurityEnvelopeValidator): Validates all mandatory sec:* tags against the active policy schema and calculates the SHA-256 sec:envelope_hash signature.

Enrichment SPI and Monotonic Elevation

The enrichment stage supports custom DLP (Data Loss Prevention: automated software tools that detect and prevent the exposure of sensitive data) scanners, regex matchers, and structural header parsers via the ChunkSecurityEnricherSPI. All enrichers must adhere to the Monotonic Classification Invariant: an enricher can elevate a chunk to a higher classification tier, but it can never weaken the parent document's baseline classification.

PYTHON 
# langchain_security_extension/security_adapter_langchain/ingestion.py
from typing import Dict, Any
from langchain_security_extension.security_adapter_langchain.ingestion import ChunkSecurityEnricherSPI, ChunkEnrichmentContext
from langchain_security_extension.security_core.constants import (
    SEC_CLASSIFICATION_LEVEL,
    SEC_CLEARANCE_FLOOR,
    CLASSIFICATION_CLEARANCE_MAP,
)

class HeadingClassificationEnricher(ChunkSecurityEnricherSPI):
    """Enricher that elevates chunk classification based on structural Markdown headers."""

    def enrich_chunk(self, context: ChunkEnrichmentContext) -> Dict[str, Any]:
        envelope = dict(context.metadata)
        parent_clearance = int(envelope.get(SEC_CLEARANCE_FLOOR, 0))

        detected_tier = self._extract_heading_classification(context.text)
        if detected_tier:
            detected_clearance = CLASSIFICATION_CLEARANCE_MAP.get(detected_tier, 0)
            # Monotonic Elevation Invariant: Never downgrade below parent baseline
            if detected_clearance > parent_clearance:
                envelope[SEC_CLASSIFICATION_LEVEL] = detected_tier
                envelope[SEC_CLEARANCE_FLOOR] = detected_clearance

        return envelope

Admission Control & Ingestion Policy Modes

When an unlabelled or malformed chunk reaches the validation boundary, the admission controller in SecurityEnvelopeValidator can be set to enforce one of three operational fallback policies configured via SecureVectorStoreIngestor.create(..., ingestion_mode=...) or the security.ingestion.mode application property. These modes are defined in langchain_security_extension.security_core.constants:

Everything Classified
(Quarantine Mode)		 INGEST_MODE_EVERYTHING_CLASSIFIED
("EVERYTHING_CLASSIFIED")		 Elevates unlabelled chunks to RESTRICTED, sets sec:quarantined = True, and allows batch completion. Preserved; accessible only by top-clearance personnel.
Everything Public
(Public Fallback)		 INGEST_MODE_EVERYTHING_PUBLIC
("EVERYTHING_PUBLIC")		 Defaults unlabelled chunks to PUBLIC (clearance 0) and permits standard read access. Preserved; sec:tenant_id remains strictly isolated to prevent cross-tenant exposure.
