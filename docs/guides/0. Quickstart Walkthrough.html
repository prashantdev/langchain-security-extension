Chapter 0: Quickstart Walkthrough — "Seeing is Believing" Hands-On Demo

Security architectures are often presented in abstract concepts. The goal of this walkthrough is to provide an immediate, hands-on demonstration of the difference between standard perimeter-only LLM applications and deterministic, code-level Policy Enforcement Points (PEPs).

By pairing the langchain-security-extension library with its live companion reference demonstrator, langchain-enterprise-incident-assistant, you will run functional and adversarial tests against two Git branches:

  • main branch (Unhardened Baseline): A standard FastAPI + LangChain IT Incident Assistant with HTTP Bearer JWT authentication, standard prompt-based instructions, and native tool execution. Demonstrates how easily standard LLM applications are exploited via prompt injection, argument tampering, cross-tenant RAG leaks, and runaway loops.
  • secured branch (Hardened Target): The identical application hardened with langchain-security-extension. Demonstrates how code-level PEPs deterministically intercept every exploit before LLM tokens are wasted or unauthorized Python callables run.

Step 1: Environment & Repository Setup

1. Prerequisites

  • Python 3.9+: A shared Python virtual environment.
  • Configured LLM Service: The demonstrator issues real model calls during triage and remediation. By default, it connects to a local Ollama instance (http://localhost:11434 with model llama3.2:3b). Alternatively, you can configure any OpenAI, Gemini, or Claude compatible endpoint in config.properties.

2. Clone Repositories Side by Side

Clone both repositories into a common workspace directory:

BASH 
# Create and activate a shared virtual environment
python3 -m venv .venv
source .venv/bin/activate

# Clone the security extension library
git clone https://github.com/prashantdev/langchain-security-extension.git

# Clone the companion incident assistant demonstrator
git clone https://github.com/prashantdev/langchain-enterprise-incident-assistant.git

3. Install the Library and Demonstrator

Install the library in editable development mode, followed by the assistant application dependencies:

BASH 
# Install library
cd langchain-security-extension
pip install -e .

# Install assistant and test dependencies
cd ../langchain-enterprise-incident-assistant
pip install -e ".[dev]"

4. Verify LLM Service Availability

Ensure your configured LLM backend is running. For local Ollama users:

BASH 
# Ensure Ollama is active and model is pulled
ollama serve &
ollama pull llama3.2:3b

Configuring Alternative Providers: To point to OpenAI, Google Gemini, or Claude instead, edit config.properties in langchain-enterprise-incident-assistant and set model1.baseUrl, model1.modelclass=openai, model1.modelname, and model1.apikey.

Step 2: Testing the Unhardened Baseline (main Branch)

First, observe how standard perimeter security behaves under both legitimate operations and adversarial exploit attempts.

1. Checkout the main Branch & Start the Server

Open Terminal 1 to run the assistant server:

TERMINAL 1 langchain-enterprise-incident-assistant (main)
BASH 
git checkout main
./startserver.sh

The server starts an embedded FastAPI service listening on port 8080.

2. Run the Basic Functional Suite (--suite basic)

In Terminal 2, run the baseline functional test suite:

TERMINAL 2 Run Basic Security Suite
BASH 
./run-security-suite.sh --suite basic

Expected Outcome: All 15 / 15 tests PASS. Standard P1 outages are triaged, password resets work, and unauthenticated HTTP calls without Bearer tokens are rejected at the FastAPI perimeter.

3. Run the Guardrail Exploit Suite (--suite guardrail)

Now, run the 31 adversarial exploit tests against the unhardened baseline:

TERMINAL 2 Run Guardrail Suite on Unhardened Baseline
BASH 
./run-security-suite.sh --suite guardrail

Expected Outcome: All 31 / 31 tests FAIL (Exploits Succeed):

  • Exploit: Unauthorized employees trick the agent into rebooting production database servers (web-prod-01) via prompt overrides.
  • Exploit: DevOps engineers targeting finance infrastructure bypass department checks because arguments are not validated before execution.
  • Exploit: Clearance Level 1 callers retrieve classified Level 3 runbooks from ChromaDB because standard RAG lacks pre-retrieval filtering.
  • Exploit: Denied tools cause the LLM to enter runaway retry loops, burning hundreds of unnecessary tokens.
  • Exploit: Sensitive API keys, passwords, and PII are logged in plaintext to application logs.

Step 3: Testing the Hardened Implementation (secured Branch)

Next, switch to the hardened target implementation utilizing langchain-security-extension.

1. Checkout the secured Branch & Restart the Server

In Terminal 1, stop the running server (Ctrl+C), checkout the hardened branch, and restart:

TERMINAL 1 langchain-enterprise-incident-assistant (secured)
BASH 
git checkout secured
./startserver.sh

2. Run the Basic Suite

In Terminal 2, re-run the basic suite to verify that hardening introduced zero regressions into legitimate workflows:

TERMINAL 2 Verify Basic Operations on Secured Branch
BASH 
./run-security-suite.sh --suite basic

Expected Outcome: All 15 / 15 tests PASS.

3. Run the Guardrail Suite

Run the 31 adversarial exploit tests against the hardened server:

TERMINAL 2 Verify Hardened Defenses on Secured Branch
BASH 
./run-security-suite.sh --suite guardrail

Expected Outcome: All 31 / 31 tests PASS (Exploits Defeated):

  • @secured_tool intercepts and hard-aborts unauthorized calls in Python bytecode before tool functions run.
  • Common Expression Language (CEL) rules deterministically block department mismatches (PARAMETER_CONSTRAINT_FAILED).
  • SecureRetriever injects native VectorStore AST pre-filters and prunes documents before they enter the prompt context window.
  • RetryBudgetTracker halts brute-force tool retry loops after consecutive policy denials.
  • In-flight DLP sanitizes PII, Luhn-valid credit cards, and API secrets before telemetry is published to the background SIEM buffer.

Step 4: Trying Individual Exploit Tests

You can execute individual test scripts to inspect raw HTTP requests, agent thoughts, and diagnostic error codes in detail.

Scenario A: Testing Dynamic CEL Parameter Constraints

BASH 
./internal-security-guardrail-tests/08-cel-parameter-department-mismatch-blocked.sh

What happens: An authorized DevOps user attempts to reboot finance-db-01. The @secured_tool evaluator dynamically looks up server ownership via EntityAttributeResolverSPI, detects that the server belongs to FINANCE while the caller is in INFRA, and aborts with diagnostic code PARAMETER_CONSTRAINT_FAILED.

Scenario B: Testing Indirect Prompt Injection Neutralization

BASH 
./internal-security-guardrail-tests/23-prompt-injection-blocked.sh

What happens: An inbound incident ticket contains a jailbreak string attempting to override system instructions and exfiltrate secrets. The entry PEP halts execution and emits a PROMPT_INJECTION_DETECTED security event to SIEM.

Scenario C: Inspecting SIEM Audit Streaming

BASH 
tail -n 15 logs/security-audit.json | jq .

What happens: Inspect the live structured RFC 5424 / OCSF audit log containing cryptographic trace correlations (W3C traceparent), redacted PII fields, and deterministic denial reason codes.
