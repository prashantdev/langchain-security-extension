Chapter 11: Enforcing Multi-Tenancy: Isolating Workspaces, Chunks, and Execution Bounds

In enterprise AI architectures, multiple customers, business units, or project teams often share foundational models, inference infrastructure, and vector storage engines. Without strict perimeter enforcement and cryptographic partition checks, shared infrastructure risks critical cross-tenant data exfiltration: an agent acting on behalf of Tenant A might retrieve sensitive knowledge or invoke infrastructure tools belonging to Tenant B. Multi-Tenancy requires treating tenant boundaries as non-negotiable hard perimeters that are evaluated continuously across agent entry gates, ingestion pipelines, vector retrieval queries, and tool execution boundaries.

In this chapter, we use the incident response assistant (langchain-enterprise-incident-assistant) as an enterprise case study to demonstrate how to enforce multi-tenant isolation across your application stack using langchain-security-extension. We examine how to configure tenant perimeters on entry runnables, inject mandatory tenant filters into vector retrievers, and eliminate ad-hoc web filter checks in favor of declarative Policy Enforcement Points (PEPs).

The Strict Multi-Tenancy Invariant

The Strict Multi-Tenancy Invariant dictates that a tenant boundary can never be bypassed or weakened, regardless of administrative role elevation, user clearance levels, or permissive fallback policies:

  • Ingestion Partitioning & Permissive Mode Invariant: Every embedded vector chunk must be stamped with a mandatory sec:tenant_id. Chunks lacking valid tenant metadata are rejected atomically during document indexing. Under permissive ingestion modes (e.g., Everything Public or quarantine elevation), the sec:tenant_id invariant is strictly preserved: while classification may default to public access, chunks strictly retain their origin sec:tenant_id and are never exposed across foreign tenant boundaries.
  • Deterministic Filter Push-Down & Defense-in-Depth: Retrievers never query vector databases with unconstrained wildcards. Pre-filter Abstract Syntax Trees (AST) always bind an explicit tenant equality check: {SEC_TENANT_ID: identity.tenant_id}. Unauthenticated queries inject a deny-all sentinel (__DENY_ALL_UNAUTHENTICATED__). As a second line of defense, if a vector store profile only supports partial AST filtering (or fails to filter), SecureRetriever executes post-retrieval in-memory pruning against candidate chunks.
  • Entry Perimeter Gate: Agent entry points configured with SecureRunnable validate that the caller's tenant_id is within the permitted boundary set (e.g., ALLOWED_TENANTS). Breaches trigger an immediate TenantIsolationError and high-severity threat alert (TENANT_BOUND_VIOLATION).
  • Multi-Agent Workflow Preservation: Multi-tenancy is preserved across multi-agent workflows by propagating the authenticated caller identity in-band inside LangChain's native run_config (via SecureRunnable.handoff), preventing tenant stripping or escalation across execution bounds.
  • Zero Cross-Tenant Contamination: Foreign-tenant access attempts immediately halt execution, return HTTP 403 with BLOCKED_TENANT telemetry, and emit a TENANT_BOUND_VIOLATION event to the SIEM.

Multi-Tenant Enforcement Across Lifecycle Tiers

Multi-tenancy is maintained as an ambient invariant across every tier of the agent and knowledge pipeline:

Pipeline Tier Enforcement Mechanism Policy Invariant Violation Handling
Agent Entry Gate SecureRunnable & EmbeddedPolicyEngine Caller tenant_id must match target_tenant configured boundary Raises TenantIsolationError; returns BLOCKED_TENANT (HTTP 403)
Vector Ingestion (ETL) DocumentSecurityTransformer & SecurityEnvelopeValidator Mandatory sec:tenant_id stamped; invariant preserved across permissive & quarantine modes Atomic chunk rejection or quarantine with tenant lock; batch rolled back
Vector Retrieval (RAG) SecureRetriever AST filter push-down & PDP in-memory pruning Query AST injects {SEC_TENANT_ID: identity.tenant_id}; unauthenticated calls receive deny-all sentinel; secondary in-memory pruning Foreign chunks filtered at query time; in-memory pruning drops mismatched chunks before prompt injection
Tool Execution (PEP) @secured_tool Policy Enforcement Point (PEP) & CEL constraints Dynamic entity attribute evaluation (e.g. ownerDepartment == subject.dept), clearance floors, and parameter constraints Mutative tools: hard abort (STATUS_BLOCKED_BY_POLICY); read-only tools: soft refusal

Tool PEP Multi-Tenancy & Dynamic ABAC: While hard tenant perimeters are anchored at agent entry gates and knowledge retrievers, the @secured_tool Policy Enforcement Point (PEP) enforces in-band tenant isolation on tools that consume explicit tenant identifiers (e.g., args.tenant_id == subject.tenantId) or dynamically resolve tenant ownership via asset registries. For a comprehensive guide on defining CEL rules, dynamic entity hydration, and dual-mode PEP enforcement contracts, see Chapter 7: Guarding Tools and Enterprise APIs.

Entry Gate Tenant Isolation in SecureRunnable

At the agent entry boundary, SecureRunnable inspects the caller's authenticated identity against the configured target_tenant boundary set. When engine.enforce_strict_tenant_isolation = True is enabled on the Policy Decision Point (PDP), any cross-tenant mismatch immediately logs a TENANT_BOUND_VIOLATION event with SEVERITY_CRITICAL_ALERT directly within pdp.evaluate(). The factory method AgentAccessDeniedException.for_agent() detects the TENANT_MISMATCH diagnostic reason and raises a typed TenantIsolationError.

langchain_security_extension/security_adapter_langchain/runnable_guard.py

SECURITY LIBRARY SNIPPET (INFORMATIVE) langchain_security_extension/security_adapter_langchain/runnable_guard.py
PYTHON 
class SecureRunnable:
    """Wraps LangChain runnables with entry authorization and tenant isolation boundaries."""

    def _evaluate_entry_access(self, config: Optional[Dict[str, Any]]) -> SecurityIdentity:
        identity = IdentityBridge.extract_from_config(config) or IdentityBridge.resolve_identity(None)
        self._prepare_config(config, identity)

        tenant = self._target_tenant if self._target_tenant is not None else identity.tenant_id
        request = PolicyEvaluationRequest.create(
            subject=identity,
            action=ACTION_AGENT_INVOKE,
            resource={
                "target_id": self._agent_name,
                "tenant_id": tenant,
                "required_roles": self._required_roles,
                "min_clearance": self._min_clearance,
            },
            context={"config": config} if config else {},
        )

        decision = self._pdp_engine.evaluate(request)
        if not decision.is_permitted:
            # PDP automatically logs TENANT_BOUND_VIOLATION with CRITICAL_ALERT under strict tenant isolation
            raise AgentAccessDeniedException.for_agent(
                agent_name=self._agent_name,
                message=f"Agent invocation denied for '{self._agent_name}': {decision.diagnostic_reason}",
                diagnostic_reason=decision.diagnostic_reason,
            )
        return identity

Full Delegation: Cleaning HTTP Filters of Ad-Hoc Tenant Checks

In conventional web applications, developers frequently rely on custom HTTP middleware or API filters to inspect incoming tenant headers (e.g., if tenant not in allowed: raise HTTPException(403)). While simple web filters work well for standard, single-shot REST requests, they are inadequate for enterprise GenAI architectures. Once a request passes through a web filter into an autonomous agent pipeline, sub-agents, asynchronous tool runners, and vector retrievers lose visibility into the HTTP context unless complex thread-locals or global state are maintained.

By delegating tenant perimeter checks entirely to the security library's SecureRunnable and EmbeddedPolicyEngine, your enterprise codebase eliminates scattered, hardcoded tenant checks from web middleware. Instead, tenant validation is anchored directly into the LangChain execution lifecycle, providing in-band propagation, centralized audit attribution (TENANT_BOUND_VIOLATION), and typed exception flows (TenantIsolationError). Code Hardening: Intercepting Cross-Tenant Breaches in API Routers

Enterprise API routers that serve agent workflows must intercept security policy exceptions cleanly at the transport boundary. Rather than letting authorization failures bubble up as unhandled 500 errors or leaking stack traces, your API endpoints should catch typed TenantIsolationError exceptions. This allows the API to terminate foreign tenant access immediately, record structured telemetry, and return an HTTP 403 response before model tokens or compute resources are consumed. In the reference implementation, this defense is organized across two distinct operational phases in app/routers/tickets.py:

Phase 1: Inbound Identity Resolution & Triage Entry PEP

At your API's front door, the endpoint extracts the caller's authenticated identity and translates it into a native LangChain RunnableConfig via IdentityBridge.create_runnable_config(). Retrieval AST Tenant Partition Push-Down

In enterprise RAG architectures, multi-tenancy cannot rely on system prompts instructing the model to "only read runbooks for your organization"—a pattern vulnerable to prompt injection and retrieval leakage. Retrieval must enforce tenant isolation at query compilation time using Deterministic Filter Push-Down: SecureRetriever automatically injects {SEC_TENANT_ID: identity.tenant_id} into the vector store AST filter, ensuring foreign-tenant chunks are excluded at the database index layer before similarity vectors are compared.

PYTHON 
class SecureRetriever:
    """Wraps vector store retrievers with AST pre-filtering and post-retrieval clearance pruning."""

    def build_full_ast(self, identity: Optional[SecurityIdentity]) -> PrefilterAST:
        """Constructs unconstrained full AST from SecurityIdentity pushing down tenant boundary."""
        if identity is None or identity.is_anonymous or identity.subject_id is None:
            return PrefilterAST({SEC_TENANT_ID: "__DENY_ALL_UNAUTHENTICATED__"})

        and_clauses: List[Dict[str, Any]] = [
            {SEC_TENANT_ID: identity.tenant_id},
            {SEC_CLEARANCE_FLOOR: {"$lte": identity.clearance_level}},
        ]
        if identity.roles:
            and_clauses.append({SEC_ALLOWED_ROLES: {"$in": list(identity.roles)}})
        return PrefilterAST({"$and": and_clauses})
